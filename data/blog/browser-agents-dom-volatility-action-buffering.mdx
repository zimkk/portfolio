# The 3-Second Blindspot: Solving DOM Volatility in Vision-Based Browser Agents

Vision-based computer-use and browser agents are nothing short of magical when navigating static websites.

On a modern enterprise Single Page Application (React, Vue, Next.js, or Angular), it fails **nearly 50% of the time**.

Why? Because between the moment the screenshot is taken ($T_0$) and the moment the model returns its planned $(x, y)$ coordinate click ($T_0 + 3.2\text{s}$), an asynchronous toast notification mounted, shifting the grid down by 64 pixels.

The agent clicks empty whitespace.

![Browser Agent DOM Volatility and A11y Anchoring](/images/blogs/browser-agent-dom.svg)

## The Solution: Accessibility Tree Anchoring

```python:browser_anchor.py
async def execute_anchored_click(page, planned_coords: dict, semantic_hint: str):
    # Wait for DOM mutations to settle
    await page.evaluate("""() => new Promise(resolve => setTimeout(resolve, 80))""")
    
    # Resolve element on live Accessibility tree
    element = await page.evaluate_handle(f"""({{x, y, hint}}) => {{
        let target = document.elementFromPoint(x, y);
        if (!target || target.tagName === 'DIV') {{
            return Array.from(document.querySelectorAll('button, a, input')).find(el => el.innerText.toLowerCase().includes(hint.toLowerCase())) || target;
        }}
        return target;
    }}""", {"x": planned_coords["x"], "y": planned_coords["y"], "hint": semantic_hint})
    
    box = await element.bounding_box()
    if box:
        await page.mouse.click(box["x"] + box["width"]/2, box["y"] + box["height"]/2)
```
