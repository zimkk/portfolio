# Why Fixed-Token Chunking Destroys Code Search (And How AST-Aware Splitting Fixes It)

If you use standard `RecursiveCharacterTextSplitter(chunk_size=512, chunk_overlap=50)` on a Python or TypeScript codebase, you are quietly destroying your code search accuracy.

Code is not prose. It is a hierarchical, typed **Abstract Syntax Tree (AST)**.

When a fixed-character splitter hits token 512, it happily slices a function right through a nested `for` loop:
- Chunk A gets the function signature and first three variable declarations.
- Chunk B gets the return statement and error handler with zero knowledge of what function it belongs to.

When an engineer searches: *"Where do we handle the Stripe webhook signature verification?"*, neither chunk contains enough self-contained context to achieve a high embedding similarity score.

Here is how to use **Tree-Sitter AST-Aware Chunking** to preserve 100% semantic scope.

## The AST-Aware Splitting Architecture

```python:ast_code_chunker.py
import tree_sitter_python as tspython
from tree_sitter import Language, Parser
from typing import List, Dict

PY_LANGUAGE = Language(tspython.language())
parser = Parser(PY_LANGUAGE)

def extract_ast_code_chunks(source_code: str, max_chunk_lines: int = 60) -> List[Dict[str, Any]]:
    tree = parser.parse(bytes(source_code, "utf8"))
    root_node = tree.root_node
    chunks = []

    for node in root_node.children:
        # Respect syntactic boundaries: Functions, Classes, Decorators
        if node.type in ("function_definition", "class_definition", "decorated_definition"):
            chunk_text = source_code[node.start_byte:node.end_byte]
            
            # Attach structural metadata breadcrumb
            chunks.append({
                "type": node.type,
                "name": node.child_by_field_name("name").text.decode("utf8") if node.child_by_field_name("name") else "anonymous",
                "start_line": node.start_point.row,
                "end_line": node.end_point.row,
                "content": chunk_text
            })
            
    return chunks
```
